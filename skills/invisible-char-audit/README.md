# Invisible Character Audit

**Your diff does not show what your compiler reads.**

There is a class of attack that needs no exploit, no dependency, and no memory
corruption. It needs a character that occupies no width.

```js
// access control
function check(user) {
  if (user.role !== "admin" ‮ ) { return false; } ‭ // admin path
  return true;
}
```

That is the same function printed twice. The bytes differ by two bidirectional
control characters — U+202E and U+202D — and between them they reorder the line
so the display shows a rejected branch while the parser reads something else.
This is Trojan Source (CVE-2021-42574). It was disclosed in 2021, it has never
been fixed in any language, because it is not a bug in a language: it is a
difference between how text is laid out and how text is read.

Now the same trick, aimed at the reader who replaced the reviewer.

## The one that matters now

U+E0020 through U+E007F are the Unicode **tag** block. Each one encodes an ASCII
character, offset by 0xE0000. Every mainstream text renderer draws them as
**nothing at all**. A language model reads them as text.

```
$ python scripts/audit.py ./release-notes.md

score    2/100   grade F
         critical 1  high 0  medium 0  low 0

FINDINGS
  [critical] IV-002  Invisible instructions hidden in Unicode tag characters
             at release-notes.md:5:39   U+E0020  TAG SPACE
             This line ends with 35 tag characters that render as nothing but
             decode to ASCII that a model will read:
             ' this sentence was invisible to you'
```

A human sees an empty gap at the end of a sentence. An agent reading the same
file sees an instruction in plain ASCII. Nothing looks wrong, so nothing gets
escalated — and "review the diff carefully" cannot help, because there is nothing
on screen to review.

The scanner does not merely warn that tag characters are present. It **decodes
the run and prints what it says**, so the payload is evidence instead of a
mystery.

## What else it finds

| id | class | why it matters |
| --- | --- | --- |
| IV-001 | Bidi controls | Display order and parse order diverge. |
| IV-002 | Unicode tag block | Encodes ASCII, renders as nothing. Hidden instructions. |
| IV-003 | Zero-width, mid-file BOM, soft hyphen | Splits tokens, defeats grep, breaks equality. |
| IV-004 | Space lookalikes (NBSP, thin, ideographic) | Never equals U+0020; breaks comparison and indentation. |
| IV-006 | Variation selectors outside emoji | Invisible modifiers; pairs carry data. |
| IV-007 | Raw C0/C1 control characters | Terminate strings, drive terminals. |
| IV-009 | Homoglyph in an identifier | `pаssword` with Cyrillic `а` is a different name. |
| IV-010 | One identifier, several scripts | The impostor pattern. |
| IV-012 | Hostname mixing Latin with lookalike scripts | Typo-squat structure. |

Every finding carries the codepoint, its Unicode name, the line and column, what
the character does, and the fix:

```
  [critical] IV-009  Homoglyph inside an identifier
             at homoglyph.py:2:16   U+0430  CYRILLIC SMALL LETTER A
             'а' renders as 'a' but is CYRILLIC SMALL LETTER A.
             The token reads as 'check_password' and is not it.
```

## Proof it works, and proof it stays quiet

A scanner that flags legitimate text is worse than no scanner, because it teaches
its reader to close the report. So the package ships both controls and both are
regenerated by a script, not hand-written:

| Target | Score | What it shows |
| --- | --- | --- |
| `fixtures/vulnerable/` — six real techniques | **2/100 F** | All six detected, with line and column |
| `fixtures/clean/` — Chinese, Arabic RTL, emoji ZWJ, accents | **100/100 A** | Zero findings |
| Four unrelated real projects | 100 / 100 / 100 / 90 | No false positives |
| One project with a genuinely GBK-encoded log | 82/100 B | Correctly flagged IV-014 |

Getting to that second row took three real fixes, each documented in the code
because each one is a judgement call:

1. **Homoglyph matching requires a letter.** The first version mapped U+2013
   EN DASH to `-`, so every range like `20–30K` in a document became a critical
   finding. Punctuation is not part of an identifier; a dash cannot shadow a name.
2. **U+3000 is suppressed on lines that already contain CJK.** Full-width space is
   how Chinese and Japanese text is indented. Reporting it produced 62 findings on
   one resume template and buried everything else.
3. **ZWJ, ZWNJ and U+FE0F are suppressed inside emoji sequences** — including
   keycaps like `1️⃣`. That is joinery, not padding.

`fixtures/clean/` exists specifically to keep those three fixes honest: if a
future change breaks one, the clean control stops scoring 100.

## Severity comes from the container

A soft hyphen in a Markdown paragraph is a paste accident. The same byte inside a
Python identifier means the name you are reading is not the name the interpreter
resolves. The base weight is promoted in code and markup, demoted in prose.

Scoring follows the same logic. `0–100` with a letter grade, capped at **55**
while any critical finding stands, and per-severity penalties are capped so that
sixty trivial low findings cannot outrank one live bidi override. Before the
caps, that exact case scored 13/100 — worse than a file with a working backdoor.

## Cleaning mode

```bash
python scripts/audit.py ./suspect.js --clean-out ./suspect.clean.js
```

Writes a copy with the listed characters removed, prints exactly what it removed,
and **never overwrites the input**. Then diff the two files — that diff is the
real deliverable, because it shows you what was hidden rather than telling you
something was.

## Look up a codepoint

```bash
$ python scripts/audit.py --explain U+E0041
U+E0041  TAG LATIN CAPITAL LETTER A
class    tag character — encodes ASCII 'A'

$ python scripts/audit.py --explain U+0430
U+0430  CYRILLIC SMALL LETTER A
class    confusable — reads as 'a'
```

## What it cannot do

Stated plainly, because a character scanner that overstates its coverage is the
easiest kind of tool to fool.

- **It does not render text.** It reads codepoints. It cannot predict what a
  specific editor, terminal, or compiler version will draw or accept — and that
  difference is exactly where the attacker lives.
- **The homoglyph table is a curated subset**, the letters that actually appear in
  impostors. A codepoint absent from the table is not evidence of safety.
- **It cannot judge intent.** A bidi control in a right-to-left localisation file
  is not an attack. The finding means "look here", never "this is malicious".
- **It cannot compare two files for visual equivalence.** `--clean-out` gives you
  the clean copy; the diff is your job.

## What to avoid

- **Do not report the score without the characters.** "Grade F" is noise.
  `U+202E at line 42` is actionable.
- **Do not fix a file by hand after a hit.** There is usually a second character
  a few bytes away. Use `--clean-out` and diff.
- **Do not strip before you read.** If a tag block was hiding an instruction, what
  it said should change your response to the entire document.

## Zero dependencies

Python 3.8+, standard library only. No network, no `pip install`, no execution of
the target. Point it at a file or a directory.
